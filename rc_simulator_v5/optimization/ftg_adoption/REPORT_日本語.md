# Follow the Gapの通常走行への採用

起動時の走行プログラムを `examples/sonic_drive_follow_gap.py` に変更しました。従来版は `examples/sonic_drive_three_laps.py` と `Previous_Best.py` に保持しています。５つの超音波距離とdtだけを入力する単独のPythonプログラムです。

FTGは検出した反射点を車体半幅と安全余裕で膨らませ、-60〜+60度の５度刻みの進行候補を分類し、連続したギャップから幅・既存の局所目標を考慮して進行方向を選びます。狭い通路だけでなく余裕のある通常走行でも目標がギャップ内か評価します。操舵はピュアパシュートに基づき、目標への補正と操舵変化量を制限します。推定ギャップがない場合は安全停止します。

曲がり角、大きな操舵、仕切り端、接近した障害物では既存の安全制御を優先します。この場面でFTGによる追加補正は使いません。Five-ray FTGはLiDARの密な走査ではなく、センサー間の領域や壁端を十分に観測できません。コース座標・GPS・壁の既知座標・カメラは走行判断に使いません。

センサー画面の緑の帯は通常走行でFTGが選んだ領域です。緑の矢印は目標方向、白点線は操舵指令の曲率です。安全制御を優先する場面や停止時はギャップの帯を表示しません。帯は通過可能性の候補であり、未観測領域の安全を保証するものではありません。従来プログラムの表示も引き続き動きます。

## 比較と検証

24案を比較しました。FTG補正を通常走行に無条件で広げた最初の12案は完走できず、衝突した案もあり不採用です。安全制御を優先した12案は基準条件の連続３周を衝突・危険接近なしで完走しました。保守的な14番（先読み85cm、補正上限１度）を採用しました。

採用版の追加10回は完走2/10・衝突0/10・危険接近合計6で、従来と同じです。成功した２回はノイズなしの同じ基準条件の繰り返しです。８回のノイズ・開始姿勢変更条件は安全停止し、安定完走はまだ未達です。

基準条件のラップタイムは131.270712 / 132.046786 / 132.099603秒、３周395.417102秒、TOTAL SCORE514.55、蛇行9、急ハンドル0、不要停止0です。従来と同じ軌跡・時間でした。通常走行の3,527制御周期でギャップを評価しましたが、基準条件では従来の目標が選択ギャップ内にあり追加操舵補正はありませんでした。今回FTGの適用・確認範囲は拡大しましたが、速度や完走率の向上は実証していません。

collision・物理・コース・評価ロジックは変更していません。以前の最高総合スコア版520.85は `optimization/divider_flow/Score_Best_Version.py` に保持しています。comparison.csvが24候補、final_validation.csv/jsonが最終ソースの実ワーカー10回、final_logsがその測距・走行記録、selection.jsonがソースSHA-256と選択結果です。

再現：`python -m optimization.evaluate_three_laps examples/sonic_drive_follow_gap.py --external --name my_ftg`。ノイズ等の追加10回は `python -m optimization.validate_follow_gap`。

152件のテスト、最大測距の除外、前方と右の障害物から左ギャップを選ぶこと、ギャップなし・測距異常・近接での停止、選択領域表示、従来の矢印表示、GUI２タブの開閉を確認しました。
