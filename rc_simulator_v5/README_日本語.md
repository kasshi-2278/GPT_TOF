# RCシミュレーター V5 — 外部Python・超音波センサー走行

## 減速ペナルティと２画面表示

「超音波・判断 V」または V キーで、センサー状況と障害物マップを別々のウィンドウに同時表示します。コース走行の減速には、20Hzの記録ごとに速度低下0.3cm/sを超えた分を集計し、0.02点/(cm/s)で減点します。正面60cm未満・斜め18cm未満・側方12cm未満の緊急接近では減点を免除し、安全制動をスコア上の損にしません。時間・直進加点と合わせた式、実走ログからの採点結果は `optimization/slowdown_penalty/` を参照してください。

仕切り付近で安定した反射が続く間は制動上限を20%まで戻す候補を含む６条件を実走比較しました。最速候補は基準３周395.42秒でしたが、減速・直進・蛇行を含む総合点は904.32点でした。採用版は399.14秒・912.82点で最高点を維持し、完走・衝突なし、危険接近なし、蛇行8回でした。緊急減速を外した候補は仕切りで衝突したため採用していません。

## 周回時間の加点

完走時の新しい合計スコア（`race_score`）に `max(0, 600 - ３周合計秒)` を時間ボーナスとして追加しました。400秒なら＋200点、350秒なら＋250点です。従来の１秒−１点と直進加点は残します。時間加点は衝突・プログラムエラーなしの３周完走時のみです。従来の `original_score` と直進加点までの `smooth_score` も保存します。100試行を再採点した最高は引き続き79番で、722.22＋200.86＝923.08点です。これは既存の走行結果の再採点であり、新たな走行テストではありません。履歴は `optimization/time_bonus/history.csv`、定義は `optimization/time_score.py`、再採点は `python -m optimization.time_bonus.rescore` です。GUIにも完走時の周回時間加点を表示します。

## 操舵の平滑化・直進加点での100試行

起動時のプログラムは `examples/sonic_drive_smooth.py` です。FTG・ピュアパシュート・安全回避を維持し、通常時の操舵出力に変化速度と変化速度の増減制限を追加しました。新スコアは従来スコア＋完走時に最大300点の直進割合加点です。100試行から安全に３周完走した最大新スコアの79番を採用し、基準条件で709.55→722.22点、直進65.00→67.12%、蛇行9→8回でした。３周は395.42→399.14秒で少し遅くなります。実測最大操舵速度は同じで、全操舵変化量はわずかに増えており、強いコーナー平滑化を達成したものではありません。追加10回の完走2/10・衝突0・危険接近合計6は従来と同じです。詳細と全100試行は `optimization/steering_smooth/REPORT_日本語.md`・`history.csv`、動画は `videos/smooth_three_laps.mp4` です。

## 超音波の障害物マッピング

「超音波・判断 V」→「障害物マッピング」で、５つの測距値から推定した反射点をセンサー別の色で蓄積表示します。灰色線は車体の移動軌跡、格子は100cmです。「検出点をCSV保存」で座標・時刻・センサー名・測距値を保存できます。「検出点を消去」で表示をクリアし、車体やコースのリセットでも自動消去します。画面を閉じても走行中の点は主画面の更新時に収集します。保持上限は直近30,000点です。

## 何が変わったか

V4.1のマップと画面を残し、**選択した `.py` が超音波距離から運転を決める**機能を追加しました。
初期モードは「外部Python（超音波のみ）」です。ガイド走行は初期状態では使いません。

```
仮想コース → 超音波5個 → 選択したPython → Accel/Handle または PWM → 車体運動
```

座標・方位・地図・ガイド経路・車速の正解値は、外部Pythonへの制御入力として渡しません。
位置と軌跡は確認のため画面・CSVに表示しますが、外部制御の入力とは分離しています。
このバージョンでは、ガイド経路データを持たないマップでも外部Python/手動で実行できます。

元の `.py` は書き換えません。編集中のプログラムを保存して「再読込」すれば、最初から実行し直せます。

## 起動

PCのPython 3.10以降とTkinterを使用します。Pygame、GPIO、PCA9685ライブラリのインストールは不要です。
こちらでの実行試験はLinux / Python 3.13 / Tk 8.6 / Xvfbです。ユーザーのWindows/macOSでの実行は未確認です。

Windows: ZIPを**すべて展開**して `start_windows.bat` を開きます。

ターミナルから:

```bash
python rc_simulator_v5.py
```

macOS/Linuxでは `python3 rc_simulator_v5.py` または `sh start_unix.sh` も使えます。
Tkの確認は `python -m tkinter`。見つからない場合はOSに合ったTk/Tcl付きPython環境が必要です。
インストール作業や追加パッケージの導入は自動では行いません。

## `.py`を選んで実行

1. **PY読込**で走行プログラムを選択します。
2. 自作など、信頼できるコードであることを確認します。
3. 通常は**自動判定**のまま使います。
4. **開始**で実行。起動前の「選択済み」の段階ではコードを実行しません。
5. 編集して保存したら**再読込**。車両とPythonの内部状態を初期化して新しい内容を使います。

起動直後は同梱の `examples/sonic_drive_three_laps.py` が選択済みです。開始するだけでセンサー走行を確認できます。
初期走行方向は反時計回りです。デモ開始は南向き、スタート1/2/3は東向きで、初期サンプルは右壁追従します。ガイド経路も逆順にしています。

- **一時停止**: 仮想時間を止めます。Pythonの状態は保持します。
- **1ステップ**: 仮想時間を50ms進めます。実車互換モードでは複数の物理ステップを処理します。
- **Python停止**: 子プロセスを終了し、車両を停止します。再開はリセット/再読込から。
- **リセット**: プログラムを終了して車両を初期位置へ戻します。次の開始で最初から実行します。
- **実行ログ**: `print()` と例外のファイル名・行番号を確認できます。
- **CSV保存**: 入力センサー値、指令値、速度、座標、読み込んだファイル名/ハッシュなどを保存します。
- **C**: 車両拡大追従、**F**: 全体表示。ホイールでズーム、右ドラッグで移動します。

モード・開始点・環境を変更すると、古いセンサー応答が残らないように外部Pythonを終了/初期化します。
壁の追加・削除は停止して行ってください。車両の配置変更はShift＋左クリック（手動へ切替）です。

## 読み込める形式1 — 実車のGPIO/PCA9685形式

写真の `sonic_drive.py` にある、以下の形式を対象に互換実行を実装しています。

```python
import time
import RPi.GPIO as GPIO
import Adafruit_PCA9685

# GPIO.setup / GPIO.output / GPIO.input ...
# while True: センサー読み取り → 判断 → PWM出力
pwm = Adafruit_PCA9685.PCA9685(address=0x40)
pwm.set_pwm_freq(60)
pwm.set_pwm(7, 0, 425)
pwm.set_pwm(1, 0, 435)
```

RPi.GPIO / Adafruit_PCA9685 をインポートするファイルは、自動判定で「実車互換」を選択します。
メインファイルにそのインポートがなく別の補助ファイル内にある場合などは、方式を**実車互換 GPIO/PWM**に変更してください。
対応範囲内であれば、既存の`while True`ループや距離測定関数を分解せずに読み込めます。

### PC側での差し替え

| 元の操作 | シミュレーター内の処理 |
|---|---|
| TriggerピンをHIGH→LOW | 対応する仮想センサーの距離を取得し、Echoパルスを予約 |
| `GPIO.input(echo)` | 距離に応じた仮想HIGH/LOWを返す |
| `time.time()`等でパルス長を測定 | 仮想時刻を返す。10µs刻みの測定時計 |
| `time.sleep()` | 実時間で眠らず、仮想時間の経過として処理 |
| `set_pwm()` | PWMを仮想ステアリング/駆動へ渡す |
| 開始待ちの`input()` | 画面の開始後、Enter相当の空文字を返す |
| `print()` | 実行ログへ表示 |

仮想時間は0秒起点です。時刻を「現在の日付」の代わりに使うコードには対応しません。
GPIO呼び出しでも1µsずつ仮想時間を進め、ビジーループ中のEcho変化を再現しています。
距離は各120Hzフレームのスナップショットに基づき、トリガー時にラッチします。厳密な実機タイミングの再現ではありません。
`input()`は開始時のEnter待ち用であり、対話的な数値入力やメニューには対応していません。

### 写真に基づく初期設定

`hardware.json` に定義しています。ピン番号はBOARD（物理ピン番号）です。

| センサー | Trigger | Echo |
|---|---:|---:|
| Fr | 15 | 33 |
| FrLh | 13 | 40 |
| RrLh | 35 | 37 |
| FrRh | 32 | 31 |
| RrRh | 36 | 38 |

操舵チャンネル1、駆動チャンネル7、周波数60Hz、I2Cアドレス0x40。
操舵PWMは右330 / 中央435 / 左540、駆動PWMは後退220 / 停止375 / 前進500です。
写真と実車が違う場合は、このJSONを修正してください。範囲外のPWMは黙って使わず、エラー停止します。
周波数を変えるプログラムでは、基準60Hzで同じパルス幅となる値に換算します。

### 後退時のESC

`legacy_esc_mode` の初期値は `brake_neutral_reverse` です。
最初の後退PWMをブレーキとして扱い、ニュートラルを挟んだ次の後退PWMで後退へ移ります。
ニュートラルの最低時間は仮に0.01秒です。後退は次の前進指令までラッチされます。
単純にPWMの正負を駆動へ変換する場合は `direct` を選べます。

写真にある `.sleep(0.2) → 停止PWM → .sleep(0.02) → 後退PWM → .sleep(0.3)` の順序を試験しました。
これは汎用の仮モデルで、実車ESCの型番ごとの制動・後退仕様を再現したものではありません。
実車プログラムがスリープ後に操舵PWMを出す場合、その遅れも維持します。シミュレーターが先回りして操舵を変えることはありません。

### 対応APIの範囲

- GPIO: `setmode`, `getmode`, `setwarnings`, `setup`, `output`, `input`, `cleanup`。
  `setup`/`output`は単一ピンとリスト、BOARD/BCM番号に対応します。
- PCA9685: コンストラクター、`set_pwm_freq`, `set_pwm`, `set_all_pwm`。
  設定した操舵/駆動チャンネルのみ。全消灯は仮想的なニュートラルとして扱います。
- time: `sleep`, `time`, `monotonic`, `perf_counter` と各`_ns`。
- `GPIO.cleanup()`では、写真冒頭の呼び出し順に合わせて番号方式を保持します。

gpiozero、pigpio、smbus直アクセス、GPIOイベント割り込み、GPIO.PWM、カメラ、シリアル通信、
センサー処理のマルチスレッド化などは今回の仮想化対象ではありません。
未対応APIや追加ライブラリがある場合はエラー箇所を確認し、対応範囲へ接続する必要があります。
**任意の実車プログラムが無変更で動く、という保証ではありません。**

## 読み込める形式2 — センサー判断関数

新規の制御を調整する場合は、ハードウェア操作を分離した以下の形式が使えます。

```python
def decide(sensors, dt):
    # sensorsはこの5個のみ。単位cm。
    # Fr, FrLh, RrLh, FrRh, RrRh
    if min(sensors['Fr'], sensors['FrLh'], sensors['FrRh']) < 60:
        return 0, 0, '前方が近いので停止'
    return 25, 0, '前進'
```

`decide(sensors)` だけでも動きます。通常は20Hzで呼び出し、`dt=0.05`です。
状態を保持する制御は次の形式にします。

```python
class Controller:
    def __init__(self):
        self.previous_handle = 0.0

    def step(self, sensors, dt):
        # 保存した内部状態を利用できます。
        return 20, self.previous_handle, '制御中'
```

`Controller.decide`も対応しています。戻り値は2要素か3要素のタプル/リスト、または
`{'Accel': ..., 'Handle': ..., 'comment': ...}` です。命令値は有限数で-100〜100。
`Handle > 0`は左、`Handle < 0`は右。`Accel > 0`は前進、負は後退です。
NaN/Infinity/範囲外/形式違いは、車を走らせずにエラー停止します。

この関数形式のAccelは正規化した駆動指令で、実車互換モードのESCブレーキ手順は適用しません。
関数を実車へ移す場合は、実車側のGPIO計測とPWM/ESC出力を別途接続してください。
関数の中で`while True`や待ち時間を入れず、1回分の判断を返してください。

| `examples/sonic_drive_legacy_example.py` | 写真形式のGPIO距離測定とPWMを使う、停止優先の互換サンプル |
| `examples/sonic_drive_photo_transcribed.py` | 写真から転記した7つの条件分岐とPWM処理。元の.pyそのものではない |
| `examples/sensor_reactive_conservative.py` | 初期試作。標準コースで途中停止した比較用コード |

`sonic_drive_photo_transcribed.py`では、独立した`if`と`and`/`or`の優先順位を維持しています。
特に `Fr < 35 or FrRh < 35 and ...` を勝手に括弧でまとめ直していません。
元の `.py` 全文ファイルはまだ受け取っていないため、転記版と完全に同一とは保証していません。

実車互換のサンプルをシミュレーター外で直接実行すると、実機環境では本物のGPIOを操作します。
**互換サンプルの確認は「PY読込」から行い、実車上で不用意に直接起動しないでください。**

## 検証

自動テストは `python validate_v5.py`。
走行試験を含める場合は `python validate_v5.py --trials`。
実行済みの試験結果は `reports/v5_validation.json`、画面確認は `reports/gui_v5.json` にあります。
実際にGUIの開始・停止・読込・リセット・ログ表示を操作して確認しました。

センサー走行とガイド走行は混ぜて評価していません。
今回のサンプルで、標準開始位置から120秒、約24.4mの無衝突走行を確認しました。
開始点・ノイズ・向きを変えた試験も記録しています。途中で安全停止した条件も隠さず記録しています。
**これは指定条件での有限時間試験であり、1周、全域走破、未知のコースでの無衝突を証明するものではありません。**

ヘッドレスで自分のプログラムを再現実行する例:

```bash
python run_program.py examples/sensor_drive.py --trust-code --seconds 120
python run_program.py sonic_drive.py --trust-code --interface legacy --seconds 60 --output reports/my_run
```

`--trust-code` は信頼できるコードの実行を了承する指定です。
JSON、走行CSV、printログを出力します。実車互換ではPWM時系列CSVも出力します。

## 異常時の扱いと安全上の限界

ユーザープログラムはTk GUIとは別のプロセスで実行します。
起動の応答は5秒、通常の応答は実時間1秒を目安に監視し、無応答・例外・不正値で終了させます。
その間、GUIをブロックせずに応答を待ちます。応答待ちでは物理時間も進めないロックステップ方式です。
時間倍率は目標値なので、PCやプログラムが遅い場合は指定倍率より遅くなります。

クラッシュ・終了・明示停止時にはシミュレーションを停止します。実車の停止距離の予測とは別です。
通常走行で衝突した場合も、衝突を記録して停止し、ガイド走行に自動切替して隠すことはありません。

**別プロセスはセキュリティサンドボックスではありません。**
選んだPythonは通常のユーザー権限でファイル・ネットワークなどへアクセスできます。
コードの副作用を隔離・無害化したものではありません。自作・確認済みのコードだけを実行してください。
不審なコードの解析用途には使わず、必要なら別途OS/仮想環境の隔離が必要です。

車体寸法は全長280mm、幅200mmです。前端から前輪中心まで70mm、後輪中心まで240mmで、ホイールベースは170mmです。
前後のタイヤ径は55mmです。コースの座標・寸法はcm単位で、車体寸法も内部ではcmに換算します。
超音波センサーはHC-SR04を5個使用する構成です。正面0度、左45度、左90度、右45度、右90度で、すべて車体前半分に仮配置しています。
正面は左右中央・前端から20mmです。斜め45度は前端から10mm・左右端、側方90度は前端から70mm・左右端に仮配置しています。左右の実際の取付位置が確定したら `config.py` の `sensor_specs()` を調整してください。
外部Pythonとの互換性のため入力名は維持しています。`Fr`=正面、`FrLh`=左45度、`RrLh`=左90度、`FrRh`=右45度、`RrRh`=右90度です。`Rr`という名前でも後部のセンサーではありません。
HC-SR04の測距は引き続き理想レイと仮想Echoパルスで近似しています。型番の記載だけでビーム幅・干渉などの実機特性を再現するものではありません。
速度、操舵応答、センサー取付位置・角度はまだ実測していません。
超音波は理想レイで近似し、ビーム幅、鏡面反射、干渉、検出欠落は再現していません。
実車のセンサー5個だけでは見えない方向や死角があります。センサー走行プログラムの安全性をシミュレーターが保証することはできません。

## ファイル構成と保守

- `rc_simulator_v5.py`: GUI。読込ダイアログ、再読込、停止、ログ、描画。
- `simulation.py`: GUI/ヘッドレス共通の車体・センサー・衝突・プログラム接続。
- `program_bridge.py`: プロセス生成、JSON通信、タイムアウト、ソースハッシュ確認。
- `program_worker.py`: ユーザーPythonの実行。GUIプロセス内では実行しない。
- `virtual_hardware.py`: 写真のAPIに限ったGPIO/PWM/仮想時計、ESCの仮モデル。
- `hardware.json`: ピン・PWM・周波数・仮のESCモード。
- `config.py`: 車体寸法・車速・舵角・センサー位置/角度・ノイズ。
- `maps/course_1030.json`: V4.1から継続したマップ。オレンジ表示・不要文字・黒いアイコンは削除済み。
- `tests/`, `validate_v5.py`, `gui_smoke_v5.py`: 再実行可能な検証。
- `controller_smooth.py`, `controller_photo.py`: 明示選択したときだけ使用する旧比較用制御。

物理モデル・制御ループ・仮想APIを分離してあるため、センサー配置の調整と走行プログラムの変更を独立して試せます。
APIの挙動は、Python公式のsubprocess/runpyドキュメントとAdafruit公式PCA9685 Pythonライブラリの公開APIを参照しました。
